# Fortemi Core Migration Current Surface Inventory

This is the #1685 parity ledger for replacing AIWG-owned indexing, discovery,
and search internals with `@fortemi/core` contracts. The migration invariant is
no regression: every behavior below is either preserved unchanged, improved with
an explicit delta, or held for an ADR-approved deprecation decision.

Tracker baseline: #1664 and roadmap comment issuecomment-77378 define the
sequence `#1685 -> #1684 -> #1686 -> #1687 -> (#1688 + #1689 + #1690) -> #1691`.
Closed prior art (#1487-#1496, #1578, #1624, #1626) is treated as baseline, not
work to reopen. Open slices #1551 and #1508 stay positioned as ordering gates:
#1551 waits for #1684/#1690 to decide Fortemi Core chunk/body embedding
ownership; #1508 stays deferred until #1687/#1690 settle the provider-neutral
storage/index boundary.

## Current Data Contracts To Preserve

### `MetadataEntry`

`src/artifacts/types.ts` defines the primary index node record:

- identity/source: `path`, optional `name`, `type`, `phase`
- display/search: `title`, `summary`, `tags`, optional `triggers`,
  optional `capability`
- lifecycle: `created`, `updated`, `checksum`
- graph: `dependencies`, `dependents`, typed-edge graph in
  `dependencies.json`
- AIWG capability flags: optional `kernel`, optional executable `script`

Fortemi v2 records must preserve these fields or provide an adapter projection
that is byte/JSON equivalent at public command boundaries.

### `DependencyGraph`

Current graph records are keyed by source path and have upstream/downstream
`TypedEdge[]` arrays. Plain string edges remain backward-compatible by
normalizing to `{ type: "depends-on" }`. Existing edge vocabulary includes
`depends-on`, `cites`, `cited-by`, and profile/research edge types emitted by
corpus tooling. Fortemi relationships must preserve type filters, direction,
node-resolution behavior, and old-index normalization until the ADR approves a
schema-only replacement.

### `aiwg.fortemi.index.export.v1`

The v1 export is intentionally narrow: CRM records plus `aiwg.artifact`. It is
already documented and schema-validated. #1686 must either keep this as a
compatibility export or define an explicit deprecation path. It is not enough
for the migration because it lacks skills, agents, commands, rules, flows,
providers, bundles, research, KB/memory, issues, chunks, and all-domain
relationship fields.
