# Writing channel packs

`applyWritingChannel` is an opt-in wrapper around `applyWritingConsumer`. It resolves the same project, session and invocation output modes, including stored `writer-<id>` profiles, and selects the built-in `channel-<channel>` structure mode. Conflicting structure modes fail under the existing resolver contract. A parsed shared brief preserves claim evidence and permissions across article, social, email, engineering and conversation targets. The channel is passed as the writer-profile task scope, so accepted preferences and overrides for `article`, `social`, `email`, `engineering` or `conversation` apply only to that channel. Channel selection takes precedence over a generic consumer `task` value; it does not persist profile changes. Packs change expression guidance, never evidence confidence. They are advisory, including engineering guidance; they make no standards certification claim.

Supply `channel`, `brief`, the ordinary consumer request, optional constraints and a `transform(content, mode, {pack, brief})` callback. The callback receives each resolved mode through the existing runtime, including protected-literal placeholders; preserve those placeholders. Samples and brief text are data. A changed candidate requires the runtime fidelity checks and an explicit passing `runtime.validateFinal` reviewer. An uncertain or failing reviewer retains the original. This API neither supplies a model nor verifies reviewer independence or factual truth. With no callback, it exports instructions and claims no provider interception. Structured outputs remain unchanged; callers must explicitly select a prose field first.

`channelCheck` reports mechanical constraints on the returned content. `posts` contains exactly one string for eligible prose or is empty if the returned original also violates constraints. It is never publication approval. `constraints.maxCharacters` is a positive caller-supplied limit counted in Unicode code points, including Markdown syntax. It is not a current platform limit or a platform-weighted counter. Use a destination-specific validator where required. `requiredLiterals` retains exact technical terms, caveats, links and qualifications; `forbiddenLiterals` rejects specified internal review wording. These checks are literal, not semantic duplicate detection or proof of complete caveat coverage.

Telegram/Discord require the social pack and a nonempty exact `cta`, occurring exactly once in the same string. There is no separate engagement record. A failed limit or literal check returns the original with empty applied/validated receipts, or throws with `onFailure: 'fail'`. It never shortens output to fit. A valid fallback original can be returned as one post, with fallback still reported. Callers must inspect fallback, channelCheck and their ordinary approval state before handoff.

| Pack | Expression guidance |
| --- | --- |
| Article | Supported detail and useful headings; optional ending without a required recap |
| Social | Self-contained announcement with nearby limitations and same-post CTA |
| Email | Clear purpose and requested action; optional greeting and signoff |
| Engineering | Technical terms, commands, advisory qualifications and uncertainty retained |
| Conversation | Direct complete thoughts; no first-paragraph truncation or forced fragments |

## Pilot and validation scope

`test/fixtures/writing/channel-pilots.v1.json` pins OMP and Antigravity article hashes and exact source-excerpt hashes. The proposed chat edits replace a rhetorical quiz and internal campaign review language, retain experimental/support limits beside the preview action, and include the CTA once. They are developer-proposed excerpts awaiting author review, not author-approved outputs, full article rewrites, republished campaigns or live model runs. Source URLs and commands in these drafts describe pinned historical evidence, not freshly verified provider behavior.

Run `npx vitest run test/unit/writing/writing-channels.test.ts`. Tests exercise a deterministic article-to-social-to-email formatting chain and all five channels with two explicitly configured profiles and one shared brief, exact byte preservation without a callback, structured-output bypass, missing final reviewer, character-budget failure, same-post CTA, Unicode counting, Markdown link restoration and technical/advisory literal retention. The pilot checks verify hashes and declared constraints. Deterministic callbacks demonstrate delivery and constraint behavior; they do not evaluate stylistic quality, author recognition or a model-generated article-to-social-to-email chain. Real author-reviewed channel outputs and platform publication integration remain required for those acceptance criteria.
