# AIWG — August 2025

_AIWG is a toolkit that helps AI coding agents work in a clear, reliable way. This is where it all started._

## TL;DR

August was month one. This is the birth of AIWG. It began with a smaller name: the **AI Writing Guide**. AI writing often sounds stiff and salesy. It leans on the same tired phrases. This first build set out to fix that. It gave AI clear rules to sound more like a person. It also added a way to stay smart and precise, not dumbed down. Nothing shipped to a package store yet. This was a quiet, foundational build month.

## Highlights

**1. A guide that helps AI drop the robot voice.**
What it is: a core set of writing rules, plus a long list of stiff phrases to avoid, with clear "before and after" examples.
How you'd use it: you add the guide to your AI's context, then it writes with fewer canned lines like "cutting-edge" or "seamlessly integrates."
Why it helps: the output reads like a real expert wrote it. It's easier to trust and easier to publish.

**2. Stay smart, not simple.**
What it is: extra guidance so cutting the robot voice never means dumbing the writing down.
How you'd use it: turn it on for technical or formal work, with voice notes for three settings — executive, academic, and technical.
Why it helps: you keep the real depth and the right words for your reader. You just lose the empty filler.

**3. Add only what you need.**
What it is: a usage guide that tells you which files to include for each job.
How you'd use it: start with the small core. Add a file only when the writing shows a problem you want to fix.
Why it helps: you keep your AI's context lean. That saves room and keeps things clear.

## Features shipped

**The core writing guide.** This was the heart of the first build. It laid out one idea: write like you built the thing, not like you're selling it. It came with a plain list of phrases that give AI away, good-versus-bad examples, and quick checklists you can run before you publish.

**The sophistication balance.** A second build followed close behind. It made sure the guide never traded depth for plainness. It kept technical words and hard ideas in place. It added short voice notes for three settings, so the tone fits the reader.

**The usage guide.** This showed you how to use the rest without overloading your AI. Start small. Add a file only when you hit a real need. It's the same "keep context lean" habit AIWG still follows today.

## Cross-project impact

The writing rules grew out of real work on another project, magly.net. The goal was to reuse the same quality bar across projects, not rebuild it each time. That reuse idea is the seed of what AIWG became.

## Known issues & open threads

This was a writing guide, not yet a toolkit. There was no command-line tool and no setup step. All of that came later. At this point, you used it by hand — you added the files to your AI's context yourself.

## What's next

Grow the guide into a real toolkit. Add a way to install it. Make it work across many AI coding apps. Add skills, rules, and shared memory so agents stay reliable. That's the road from this small guide to the AIWG of today.
