# AIWG now deploys to 11 AI coding tools — what shipped in 2026.6.0

![A multi-platform AI deployment framework: a central hub linked to distinct provider nodes, a knowledge-graph cluster, and an orchestration pipeline](/assets/blog/2026-6-aiwg-2026-6-0.png)

AIWG maintains a single source of truth — your agents, skills, commands, and rules — and deploys it into whichever AI coding tools you actually use. The June release expands that reach and deepens what the framework does once it gets there. Three changes lead: a new deployment target, declarative orchestration, and a research framework that now reasons over an entire corpus rather than just filing papers.

```bash
npm install -g aiwg     # fresh install
aiwg refresh            # update an existing install + redeploy
```

## OpenHuman makes eleven

[OpenHuman](https://github.com/tinyhumansai/openhuman) is an open-source personal-AI runtime — a Rust core with a Tauri desktop shell that can itself drive `claude_code` and `factory` as inference backends. It is now a first-class AIWG target:

```bash
aiwg use sdlc --provider openhuman
```

The deploy follows OpenHuman's own conventions. Kernel skills install globally to `~/.openhuman/skills/`, the ungated user-scope root OpenHuman scans on every launch — the same place its own installer writes. Personas stay workspace-scoped for the coding hosts OpenHuman drives, and commands and rules aggregate into an `AGENTS.md` bridge. We verified this against the running app: deploy AIWG, and OpenHuman's agent harness parses the skill bundles at startup and wires the triggered ones into its event bus. One honest note — OpenHuman's BETA Skills Explorer reads a different directory than the one its installer writes to, so deployed skills do not render in that panel yet. They load and run regardless; the panel is upstream's to fix.

That brings the supported set to eleven: Claude Code, Codex, GitHub Copilot, Cursor, Warp, Factory, OpenCode, Windsurf, OpenClaw, Hermes, and OpenHuman.

## Orchestration is declarative now

Release and architecture workflows stopped being prose runbooks. They are YAML Flows (`flow.aiwg.io/v1`) that `aiwg discover` surfaces directly, with gate sequences defined in config so the same skill body serves a CalVer npm project and a SemVer container-only one alike. A Flow can fan a single step across an agent panel and synthesize the results through an executor contract.

Missions extend that across stacks. One conductor dispatches heterogeneous workers — a Claude session handing subtasks to Codex subagents, for instance — over a shared `runtime:<name>` convention, and `/aiwg-mission` ships AIWG-owned on Codex with no plugin to install. (This release publishes the release process itself as the pilot Flow.)

## The research corpus learned to think

The research framework picked up the tooling that turns a pile of PDFs into something you can interrogate. Search is now both semantic and lexical — `aiwg index query --semantic` for embeddings (with `similar` and `dedup-report`), `--fulltext` for BM25. `aiwg corpus extract-crossrefs` and `citation-backfill` densify the citation graph; `integrity-scan` flags submission risk; `sidecar-lint` repairs metadata; and provider-neutral vision extraction pulls structured content out of image-only scans.

## Smaller, sharper

Discovery now matches the way people actually ask — full natural-language questions normalize to keyword phrases, and `discover` is the single agentic-capability surface that induces itself on new directives. Cross-provider polish landed across the board: Cursor emits native `.mdc` rules, OpenClaw carries a Steward identity in its `SOUL.md`, Warp's bridge slimmed from a 17,500-line aggregate to a lean discover-first file, and user-facing CLI output now points at the public repository rather than an internal build host.

Full notes are in the [changelog](https://github.com/jmagly/aiwg/blob/main/CHANGELOG.md). To try it:

```bash
npm install -g aiwg
```
