# AIWG 2026.9.1 - Governed data, broader provider reach

**Release date:** 2026-09-04

**Channel:** stable

AIWG 2026.9.1 adds governed schema and dataset workflows, introduces Pi Coding
Agent as the twelfth named provider integration, and strengthens live storage
qualification. It also turns the public provider count into a tested contract
so documentation cannot quietly drift from the implementation.

## What this changes for you

### Govern schemas and datasets as operational assets

Schema governance now provides a catalog, lifecycle policy, compatibility
analysis, and validation commands. The Dataset Intelligence addon builds on
that foundation with source-adapter contracts, standards profiles, canonical
run ledgers, provenance, orchestration commands, migration guidance, and
cross-runtime conformance checks.

Start by discovering the workflow that matches your task:

```bash
aiwg discover "govern schema compatibility"
aiwg discover "build a governed dataset pipeline"
aiwg discover "validate dataset provenance"
```

These capabilities make changes and evidence explicit. They do not certify an
external dataset or replace operator review of source rights, quality, and
fitness for purpose.

### Use AIWG with Pi Coding Agent

Pi is now an experimental first-class provider for identity, detection,
capability reporting, and native resource deployment:

```bash
aiwg use all --provider pi --dry-run
aiwg use all --provider pi
aiwg steward capabilities --provider pi
```

AIWG deploys provider-neutral startup context, portable Agent Skills, and Pi
prompt templates while respecting project and relocated user scopes. Runtime
extensions, model-catalog integration, and persisted-session ingestion remain
future work.

The canonical inventory is now explicit: 12 named provider integrations plus a
separate generic fallback adapter. Devin remains an alias for Windsurf rather
than an additional provider.

### Extend output behavior through supported APIs

The output-mode registry and protected transformation runtime are exported from
the package API. New documentation covers selection, personal and project
profiles, custom syntax, runtime integration, and troubleshooting.

### Qualify storage against live implementations

Fortemi conformance now exercises published Core receipts against clean PGlite
and live Fortemi paths. This provides concrete compatibility evidence rather
than relying only on local unit-level substitutes.
